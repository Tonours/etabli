## Findings considered and rejected

From the audit (batch 1):

- **Implement the `dynamic-workflow` / `$skill` routes claimed by the old
  audit**: rejected for now — the audit's own analysis called generic
  `workflow` wording over-broad; no current user demand. Plan 004 annotates
  the stale report instead. Revisit only on explicit request.
- **Physically share one classifier module between Node hook and Bun
  extension**: rejected for now — cross-import works in tests but is unproven
  for the deployed `~/.claude` / `~/.pi` symlink layouts; the hardened parity
  test (001) gives the drift protection at near-zero risk. Revisit if a third
  adapter appears.
- **Symlink workflow templates instead of copying**: rejected — deployed
  projects legitimately customize their copies; drift visibility (plan 009)
  is the right tool, not propagation.
- **Cap scanned output length in filter-output**: rejected — a truncated
  redaction scan is a security hole, not an optimization.
- **Wire `workflow-real-agent-scenarios.sh` into CI**: deferred — real
  agent spawns + network; plan 007 gives it `bash -n` coverage; plan 011
  covers the deterministic layer in CI instead.
- **"deploy staging → ops-stop divergence" (from the perf audit)**: rejected
  as reported — verified by execution that BOTH classifiers route it to
  `ops-stop`; the real OPS_STOP divergence is covered by plan 001.
- **nvim startup and repo hygiene**: audited, clean.

From the research handoff (batch 2 — the handoff's own "à ne pas faire"
list, adopted as standing rejections):

- **External wrapper around Pi**: rejected — no proven gap; adapters stay
  thin over the shared contract.
- **Multi-agent as default**: rejected — documented failure case for
  shared-context coding work (Anthropic multi-agent post); delegation stays
  opt-in per `workflow/skills/orchestration.md`.
- **Making the LLM deterministic**: rejected as a goal — determinism lives in
  the workflow layer (router, gates, ledgers); LLM decisions get journaled
  (plan 012), not constrained into pretend-determinism.
- **Heavy workflow framework (LangGraph/Temporal-class)**: rejected — the
  contract layer is markdown + two small classifiers + hooks; the framework
  ideas (event log, capability labels, checkpoints) land as conventions
  (plans 012/013/016), not dependencies.
- **More prompt ceremony**: rejected — every batch-2 plan adds proofs, tests,
  ledgers, or gates; none adds prompt text beyond one-line pointers.
- **Per-scenario `expected-files.txt` / `forbidden.txt` / `validation.sh`
  (handoff sketch for piste 1)**: deferred — that layer only measures real
  LLM behavior; it belongs to `workflow-real-agent-scenarios.sh` if that
  harness ever gets a nightly job. Plan 011 ships the deterministic layer
  (input.json / expected.json) only.
- **Auto-emitting ledger events from hooks**: deferred — hooks are stateless
  per-prompt; the manual convention (plan 012) must prove itself first.

## Research grounding (for the human, not the executors)

Agents* (2024) — deterministic routing over autonomy for distinct categories;
Chroma *Context Rot* + Anthropic multi-agent post (2025) — token weight is
the dominant performance lever (plan 003); Huang et al. + CRITIC, ICLR 2024 —

autonomy as verifiable contract (outcome, constraints, validation, stop) —
already encoded in PLAN.md/goal contracts; Temporal blog — deterministic
workflow around journaled non-deterministic decisions → plan 012; OpenHands
SDK paper — event log + resumable state as production-agent baseline → plan
012; SWE-bench Verified — fail-to-pass + pass-to-pass scenario structure →
plan 011; SWE-agent paper — agent-computer interface quality dominates →
supports keeping hooks/guards deterministic and legible; LangGraph docs —

plan→adversary→bounded-loop→validate→review→archive→cleanup pattern the
existing spec.md flow already implements; plans 011-016 add the missing
proof layers (scenarios, ledger, capability matrix, coverage, checkpoints).
