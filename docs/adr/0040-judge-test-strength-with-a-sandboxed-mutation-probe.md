# Judge test strength with a sandboxed mutation probe

Test gaps are the largest true-positive class in the private review corpus, and test strength was judged only by reading. `workflow/runtime/mutation-probe.mjs` judges it by execution: it mutates the added lines of a diff against a base ref (operator swaps `===`/`!==`, `==`/`!=`, `&&`/`||`, shell comparisons, `true`/`false`, deletion of `return`/`throw`/`exit` lines), runs the focused test once per mutant and lists the survivors. Implementation-loop step 12 runs it on standard and high-risk diffs that touch executable sources; each survivor gets a killing test or a one-line justification, recorded as `mutation: N survived of M, K justified`.

A throwaway prototype measured the need first (M1, five shipped commits with `--base <commit>^`): `162ba21a` 2 mutants (1 killed, 1 survived), `daf6779b` 1 (1, 0), `ee9ceba7` 2 (2, 0), `9757f99d` 3 (3, 0), `c5b01f91` 10 (8, 2); 18 mutants, 15 killed, 3 survived, no invalid or timeout. One survivor showed a real gap, closed by `1ba7204c`. M1b reran the five targets under a write-deny profile with identical outcomes and unchanged originals.

Each mutant runs in a fresh APFS clone (`cp -c -R`) of a pristine copy of the work tree that has its own git repository, and every command the probe starts (git reads, the copy, checks, the test) runs under `sandbox-exec` with a per-step profile: writes are denied and stop the writer (SIGSTOP), the temp dirs (`/private/tmp`, `/private/var/tmp`, where `/bin/bash` 3.2 writes here-documents, and the user temp dir) and each `--allow-write` are allowed, the original work tree, its git dir, its common git dir and the probe's work directory are denied again, every ancestor of those is denied as a literal so none can be renamed, and only the step's own clone is writable. Profile paths are canonical, so case, `/tmp` and firmlink aliases match. A stopped process in the step's tree (its process group and every descendant by parent pid, so a `setpgrp` timeout wrapper stays tracked) ends the step as `denied`, which is not scored; the whole tree is killed after every step. A first plan defended the original with one check per escape vector (environment, links, filters, fsmonitor, nested `.git` files, `commondir`); seven adversary rounds each found another vector, so one kernel rule set replaced them all. Git reads still neutralize filters, fsmonitor and index refresh, for diff fidelity.

## Consequences

- macOS only, and `sandbox-exec` is deprecated: without it, or inside another sandbox (macOS refuses nested profiles), the probe exits 2 with `no write sandbox` and the run records `mutation: unavailable`. There is no unsandboxed fallback. On Claude Code it runs in the unsandboxed Bash mode.
- Denial detection needs the kernel to stop the writer. macOS 14.4 accepts `(with send-signal SIGSTOP)` but returns EPERM without stopping (measured 2026-10-29; macOS 26 stops), so a denial would score as `killed`. Before any clone, the probe runs three witnesses in its own work directory under the generated profile, through a child shell: create, remove and rename. Any witness not stopped makes it exit 2 with `no write sandbox: a denied <operation> does not stop the writer`, recorded `mutation: unavailable`. Other operations are assumed to behave like these three. The test suite runs its integration cases only where a stop is observed, and the refusal case elsewhere.
- Before any command, the probe refuses hard-linked files under the protected roots (a pre-existing hard link is a path alias the kernel rule does not see) and symlinks anywhere in git metadata.
- Tests that write outside temp dirs need `--allow-write`, visible at baseline as `baseline failed: denied write by <command>`.
- Residual risks: a test that kills and reaps its own stopped child between two 100 ms polls turns a denial into `killed`, which can only overstate the score (owner decision, 2026-10-29); a descendant that detaches from the process tree (double fork, daemon) before a poll is outside the supported domain and its denial goes unseen; with SIGSTOP, a write a tool would tolerate when denied (a cache, a history file) stops it instead and counts as `denied`, so the baseline names it and `--allow-write` opens its directory; a test that delegates a write to a process outside the sandbox (Apple Events, launchd, ssh, a running daemon) is out of scope (`lsopen` is denied as a cheap guard); a test or a mutant with a deleted guard can leave stray files in temp dirs or allowed directories, and that state can carry from one mutant to the next; tests that reach code through absolute links into another checkout run the original, not the mutant.
- Lexical operators, no AST: heredoc bodies, multi-line strings and template literals, comments and quoted tokens are skipped; rare shell forms (a literal backslash or quote inside a quoted heredoc delimiter, a delimiter split by a line continuation, an escaped space before `#`) can mask too many or too few lines; survivors are checked by hand.
