# Orchestration: Pi deterministic agentic workflow loop

## Execution Rules

- Keep the original objective intact.
- Ask for approval before risky, expensive, external, or destructive actions.
- Keep immediate blocking work local.
- Delegate only bounded, disjoint, materially useful packets.
- Integrate packet results before final verification.

## Branching Rules

- If local inventory contradicts web patterns, prefer local source of truth.
- If an external pattern requires wrapping Pi, reject or defer it.
- If a recommendation cannot name evidence or a stop condition, reject it.
- If the final artifact starts becoming implementation, stop and keep it as a
  plan.

## Packet Prompts

### Packet: Local Inventory

Inspect local Pi/workflow files and produce confirmed facts, gaps, and design
implications. Do not edit runtime files.

### Packet: Web Research

Use primary or recognized sources for agent loops, deterministic controls,
roles, evals, prompt contracts, skills, hooks, and Pi primitives. Label claims
by confidence.

### Packet: Integration

Map accepted patterns onto Pi-native docs/skills/extensions/templates. Reject
external wrappers and multi-agent complexity unless evidence supports them.

## Completion Audit

- Final plan artifact exists at `docs/pi-agentic-workflow-loop-plan.md`.
- It includes local inventory, source-backed findings, target operating model,
  role contracts, routing rules, templates, skills/extensions, system-prompt
  decision, eval plan, implementation order, risks, acceptance criteria, and a
  first ticket.
- It does not ask to implement code in this goal.
- It keeps Pi as the main user-facing tool.
